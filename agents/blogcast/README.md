# Blogcast Agent — 使い方（Claude 運用ガイド）

記事（URL / ブログ / テキスト）を、**台本の型**に沿った解説動画にするエージェント。画は**gpt-imageによる自由なイラスト**（スライド風ではない）。記事 →（型）→ 絵コンテ →（gpt-image画像＋EL音声＋静止・白フェード・字幕）→ 動画。

**このREADMEは Claude Code が読んで、ユーザーを対話誘導するための運用指示です。**

---

## 尺/圧縮度プリセット（最初にこれを聞く・主動線）

「**全部入れる／ほどよく／短く、どれにします？**」と一度聞く（`--preset`）。**シーン数＝動画の尺**に直結する。

| preset | シーン数 | 使いどころ |
|---|---|---|
| **faithful**（全シーン） | 上限なし（記事を章分割・全論点） | 長い記事を漏れなく（**長尺注意・課金増**） |
| **condensed** | 20シーン以内 | ほどよい |
| **essence** | 10シーン以内 | 短く（従来の6〜14に近い） |

- 未指定は従来（6〜14シーン）。faithful は長い記事だと数十シーンになり、gpt-image＋EL の課金が増えるので**概算で必ず確認**してから `--approved`。

## 全体フロー（Claude はこう誘導する）

0. **入口ガイド** — 「記事やブログを**解説動画**にできます。**URL / Blogの article.json / テキスト**をください。台本の型と画風はこちらで提案します」
1. **記事を受け取る** — URL / `article.json`（Blogの出力）/ テキスト
2. **台本の型をAI提案** — 記事の性質で出し分け（解説記事→実用、体験談→物語 など）。指定も可
3. **画風をAI提案** — 記事から**自由文のアートディレクション**を導出（例「手描き風・生活感のある小物で地道さを伝える」）。保存名で使い回しも可
4. **絵コンテ生成（課金ゼロ）** — 型の骨格に沿って scenes（画づくりメモ＋ナレ＋視聴者向け見出し）を作成 → `storyboard.json` に固定（ナレ・型・画風は以後変わらない）
5. **概算 → 承認** — 「**画像◯枚≒◯円 ＋ 音声≒◯円 ＝ 合計約◯円**」→ OK でビルド
6. **動画ビルド** — gpt-image が各シーンの画を生成（動画バックエンドの生成機構）＋ EL音声 ＋ 静止・白フェード・字幕
7. **手直し** — 声変更やナレ微修正の再ビルドは**画像キャッシュにより数円**。絵ごと作り直す時だけ `--regen`

## コマンド早見表

`python studio-agents/agents/blogcast/cli.py <cmd> …`（リポジトリ直下から）。

| コマンド | 用途 | 課金 |
|---|---|---|
| `styles` | 台本の型 一覧 | ゼロ |
| `arts` | 保存済みの画風 一覧 | ゼロ |
| `build …` | 記事→型→絵コンテ→概算→動画 | 絵コンテまでゼロ / 動画=**gpt-image＋EL 合算概算→承認** |

### build のフラグ

| フラグ | 意味 | 未指定なら |
|---|---|---|
| `--url` / `--file article.json` / `--text` | 記事ソース | — |
| `--style` | 台本の型（下記7種） | AIが記事から提案 |
| `--art` | 画風（**保存名** or 自由文） | AIが記事から提案 |
| `--save-style NAME` | 今回の画風を名前で保存 | —（`last-blogcast` には常時自動保存） |
| `--voice` | 声6種（男: nao/shohei/ren・女: miki/maya/kazuha） | 環境変数 `DEFAULT_VOICE_PRESET`（未設定ならエラー） |
| `--approved` | gpt-image＋EL の課金を承認 | 概算だけ返して停止 |
| `--regen` | 絵コンテ（ナレ・画づくり）を作り直し。**画像キャッシュも破棄** | storyboard.json を再利用（固定） |
| `--regen-images` | 画像キャッシュだけ破棄して描き直し | キャッシュ再利用（再課金なし） |

## 台本の型（7種・動画バックエンド script_styles 流用）

- **記事忠実（本命）**：`owned_explainer_practical`（実用・手順/制度/比較）/ `owned_explainer_story`（物語・ルポ/体験談）
- **説得型**：`three_point`（結論3つ先出し）/ `pas`（悩み解決）/ `bab`（ビフォーアフター）/ `curiosity`（謎引っぱり）/ `listicle`（○個まとめ）
- いずれも「記事に無い数字・固有名を足さない」を型が持つ＝捏造しにくい

## 課金（gpt-image ＋ EL の合算）

- gpt-image：約2円/枚（低品質・実測ベース）
- EL音声：数百字で1〜4円
- **必ず「合算概算 → `--approved`」の2段**。承認前はどちらも叩かない
- **画像キャッシュ**：ビルド成功後に `slides_cache/` へ回収。声だけ変える再ビルドは**画像0円**（目安：約20円→約3円）

## 出力物

- **`video.mp4`** — 完成動画（1080p・白フェード・字幕）
- `storyboard.json` — 絵コンテ（型・画風・ナレ・見出しの固定台帳）
- `slides_cache/` — 生成済み画像（再課金回避）
- `el_job.json` — ビルド指示（デバッグ用）

## 依存

claude CLI（絵コンテ・課金ゼロ）＋ **OPENAI_API_KEY（必須）** ＋ **ELEVENLABS_API_KEY（必須）** ＋ ffmpeg ＋ uv ＋ 別途用意する動画バックエンド。`setup_check.py` で診断可。

## 既知の制約

- 承認済みビルドが途中失敗した場合、生成済み画像は projects 側に残るがキャッシュ回収は成功時のみ（リトライで再課金の可能性）
- 記事を変えたのに同じ `--out` を使うと古い storyboard を再利用する（別記事は別 out か `--regen`）
