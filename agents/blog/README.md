# Blog Agent — 使い方（Claude 運用ガイド）

ソース（記事 / 資料 / メモ / URL）から、読み物として質の高いブログ記事（＋内容の入った解説スライド図）を作る CLI エージェント。中身は 動画バックエンドのブログ生成モジュール（blog.py）の品質パイプラインを移植し、図解は slide-studio の `render_deck_ai`（Slideと同じ描画）を流用。

**このREADMEは Claude Code が読んで、ユーザーを対話誘導するための運用指示です。** ユーザーは CLI 引数を覚える必要はありません。

---

## 作り方プリセット（最初にこれを聞く・主動線）

ユーザーには「**原文に忠実に／構成を変える／短く、どれにします？**」と一度だけ聞く（`--preset`）。

| preset | 何をする | 文量 | 型 |
|---|---|---|---|
| **faithful**（原文に忠実） | 言い回しだけ整える。構成は原文のまま | 原文どおり・**全量保持** | 使わない |
| **restructure**（忠実なまま構成変更） | 内容そのまま、7型に並べ替え | 原文どおり・**全量保持** | 未指定時は `explainer`（`--structure` で指定可） |
| **compress**（要点に圧縮） | 要点に凝縮 | 約4,000字（`--target` 可変） | `--structure` |

- faithful / restructure は元ネタの**全量を保つ（凝縮しない）**。長文もそのまま。内部でチャンク分割して1対1で言い換える。
- 文体は既定 **です・ます調** に統一（`--tone` で常体などに変更可）。全チャンクで文末を揃えるので揺れない。
- preset 未指定時は従来の `--mode`（seo_long / faithful）。

## 全体フロー（Claude はこう誘導する・全自動寄り）

各ステップで聞くのは最小限。**決まっていない変数はAIが提案／推定**し、**課金（図解生成）だけは概算→承認**を取る。

0. **入口ガイド（ユーザーが迷っていたら、まずここから）** — ユーザーは型やワークフローを知らない前提。Claudeから「**元ネタ（資料/URL/メモ）をくれれば、記事の型と画風はこちらで提案します。おまかせでOK、こだわりがあれば言ってください**」と口火を切る。**選択肢（型7種・画風6種）を全部並べて選ばせない**（迷わせない）。型はAIが提案して「これでいい？」と確認する形で体験させる。
1. **ソースを受け取る** — 「何をもとに記事にしますか？」ファイル / URL / メモ（複数・混在可）。
2. **宛先を軽く確認（任意）** — 「誰向け・何のため」が明確なら投入、曖昧なら **AI推定に任せる**（聞き倒さない）。
3. **型×画風をAIが提案** — `recommend` で「この題材なら型＝◯◯・画風＝◯◯が合います」と1回提示 → ユーザーが一言OK or 変更。急ぐならこの提示も飛ばして生成へ。
4. **記事を生成（課金ゼロ）** — `build`。品質ゲート（捏造除去・再述圧縮・焦らし解消）が自動で走る。Claudeは「◯字・◯セクション、捏造◯文を除去しました」と結果を添えて **本文（article.md）を見せる**。
5. **図解を付けてHTMLまで仕上げる（標準の締め）** — 記事本文で止めず、**各セクションを解説スライド図にして図付きHTMLまで作るのが基本**。図は gpt-image 課金なので「**◯枚で約◯円**」と概算を出して承認だけ取る（承認前は生成しない）。急ぎ・図が不要なら本文だけでも可。
6. **完成物を渡す** — **図付き `article.html`（WordPress貼り付け可）が標準の成果物**。次に動画化するなら `article.json`。

> 図解の粒度は**全自動**（付ける/付けないだけ確認）。「この図だけ直したい」等の1枚単位の相談は現状スコープ外。

## コマンド早見表

`python studio-agents/agents/blog/cli.py <cmd> …`（リポジトリ直下から）。

| コマンド | 用途 | 課金 |
|---|---|---|
| `options` | 投入できる変数の選択肢（宛先/型/画風/モード）| ゼロ |
| `recommend` | ソースから画風×型をAI提案 | ゼロ |
| `build` | ソース→記事→品質ゲート→ article.json/.md/.html | ゼロ |
| `images --deck … [--approved]` | 各セクションを解説スライド図に（gpt-image・概算→承認）| 課金ゲート |

## 変数の投入（build / recommend）

`blog options` で選択肢を確認。**未指定はAIが推定/推奨、指定すると人優先**（宛先は候補外の自由記述も可）。

- ソース: `--file` / `--url` / `--text`（複数可・混在可）/ stdin
- 宛先: `--author` / `--reader` / `--purpose` / `--tone`
- 型: `--structure`（explainer / how-to / listicle / comparison / case-study / news-commentary / opinion）
- 画風: `--theme`（executive-mincho / midnight / coral-editorial / warm-serif / modern-sans / indigo-pro。**保存名も可**）
- モード: `--mode seo_long|faithful` / 長さ `--target 3500`
- その他: `--no-gates`（品質ゲートを飛ばす・検証用）/ `--save-style NAME`（画風を保存）/ `images --theme`（図解だけ別画風に）

## 同じテイストで作る（画風の保存・使い回し）

`build --save-style 名前` → 次回 `--theme 名前` で同じテイスト（直近は `last-blog` に自動保存。保存庫は5エージェント共通の `studio-agents/styles.json`、「前と同じテイストで」と言われたらここを見る）。

## 品質ゲート（seo_long で全て走る・課金ゼロ）

捏造除去（元ネタに無い具体を除去）／再述圧縮（水増しを圧縮）／焦らし解消（結論を先出し）／タイポ正規化。

## 図解（解説スライド）

各セクション → 構造化スライド（`organize` が内容に合う layout を自動選択）→ **`render_deck_ai`（Slideと同じ描画）** で gpt-image 描画。**内容・数値が入った解説スライド図**（文字なし挿絵ではない）。画風は記事の画風を踏襲。課金は概算→承認→実行。

## 出力物

`--out` ディレクトリに:
- **`article.json`** — 受け渡しの箱（構造化記事＋宛先＋型＋ソース＋ゲート結果＋画像対応）。後工程（Blogcast＝ブログ→動画）がこれを食う。
- `article.md` / `article.html`（図付きのWP貼り付け可能HTML）

WordPress自動投稿（画像アップ→URL差替→下書き投稿）は元 blog.py にあり、未移植（追加可）。動画化は別エージェント（Blogcast）。
